Security

Johnify has not had an independent security review. This page describes the design and its limits.

Protected

  • Names and message text, from anyone without the chat code
  • Integrity: modified or forged packets fail the GCM tag and are dropped
  • The code and key are never transmitted
  • Repeaters relay without being able to read anything

Not protected

  • Metadata: packet sizes, timing, group ID and stable device IDs are visible
  • The chat code is the password. There is no revocation or forward secrecy
  • A captured packet allows offline guessing of codes, at about 5,000 hashes per guess
  • On an open hotspot, anyone connected can see HTTP traffic and reset the board. Set AP_PASSWORD

Cryptography

Key derivation

SHA-256 of a version prefix and the code, then 5,000 rounds mixing the code back in. This is an iterated hash, not PBKDF2 or Argon2.

Chat codes

10 characters from a 31-character alphabet, about 49.5 bits of entropy when generated by the app.

Encryption

AES-256-GCM with a random 12-byte nonce per message. The group ID, message ID and device ID are authenticated.

Replay

A board remembers 256 recent messages. A replay after more traffic than that could be accepted again, though phones hide most repeats.
